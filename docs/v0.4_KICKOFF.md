## 2. asmdef szeparáció

**Célstruktúra (a handover szerint):**

```
FigmaRuntime.asmdef             → Core, Runtime, Tracks, Data
FigmaRuntime.Editor.asmdef      → Editor (csak editor: ref: FigmaRuntime)
FigmaRuntime.Experimental.asmdef→ Experimental (ref: FigmaRuntime)
```

**Követelmények:**
- `Experimental` NEM referenciálható a `FigmaRuntime` felől → az F6 előbb készül el (sorrend!)
- `Editor` assembly: `includePlatforms: ["Editor"]`, `references: FigmaRuntime`
- Az Overlay fájlok ISO-8859 kódolását UTF-8-ra konvertálni (a `VisualTreeUtility`-nál már megtettük — ugyanaz a művelet a 15 fájlon)
- A `#if UNITY_EDITOR`-os fájlok ellenőrzése a split után (pl. `FigmaFlowWindow`)

**Kimenet:** gyorsabb fordítás, tiszta függőségek, az Experimental ténylegesen izolált.

## 3. Editor-oldali StateCache — Startup Flash végleges megoldása

**Jelenlegi workaround (v0.3.7):** `HideRoot() → Capture → ShowRoot()` — működik, de a Runtime épít cache-t futásidőben (lassú, felvillanás-kockázat).

**Végleges terv (a handover §5.3 szerint):**
```
Import (editor) → StateCache (asset) → Runtime (betöltés) → Play
```

**✅ Implementálva (2026-08-02, ADR-009):**

| Elem | Fájl | Szerep |
|---|---|---|
| Cache asset | `Data/FigmaStateCacheAsset.cs` (új) | ScriptableObject, inline `List<CachedState>` (stateName + `List<ElementData>`) — nincs sub-asset |
| Export | `Editor/StateCacheExporter.cs` (új) | Play Mode-os export a `FigmaStateMachine.GetCapturedStates()`-ból → `Assets/FigmaFlow/Cache/` |
| Runtime | `Runtime/FigmaStateMachine.cs` (bővítve) | `stateCache` mező + `TryLoadStateCache()`: ha érvényes → nincs capture, nincs HideRoot; hiány/eltérés → fallback a runtime capture-re |
| UI | `Editor/FigmaFlowWindow.cs` (bővítve) | "State Cache" szekció: mező + Export gomb |

**Használati folyamat:**
1. Első futtatás Play Mode-ban: a fallback capture lefut (a régi workaround) — ez egyszeri
2. Motion Studio → State Cache → **Export State Cache**
3. Kilépés Play Mode-ból → az assetet a StateMachine **State Cache mezőjére** húzni
4. Újraindítás: a logban `[FigmaFlow] StateCache betöltve: N state` — **nincs felvillanás**, a workaround nem fut

**Miért Play Mode-os export?** A capture valódi layoutot igényel (worldRect / resolvedStyle). A Play Mode-os mérés megbízható; a tiszta editor-only offscreen mérés (rejtett EditorWindow/UIDocument) későbbi finomítás — nem blokkol (ADR-009).
**Megjegyzés:** a VTA-k változása után újra kell exportálni a cache-t.

## 4. Smart Overlay render pipeline (a fő feature)

**Az Overlay kutatási kód (Experimental/Overlay, 15 fájl) átemelése a Stable-be — a normál fejlesztési folyamaton át:**

```
Analysis → Builder → Motion Engine (freeze) → Overlay pipeline
```

**Rétegek (a kutatási kód alapján):**

| Kutatási fájl | Stabil szerep (v0.4) |
|---|---|
| `OverlayScene` | A Current/Target UI-n kívüli animációs réteg kezelése |
| `OverlayRenderer` | RenderPair-ek építése (Current/Target párok) |
| `OverlayBinder` | Track ↔ RenderPair kötés |
| `OverlayTransitionBuilder` | Overlay átmenet építése (a `TransitionBuilder` mintájára) |
| `OverlayTransitionPlayer` | Overlay lejátszó — a `TransitionPlayer` mintájára, az `ITransitionPlayer` interfészre emeléssel (a StateMachine player-agnostic lesz) |
| `IRenderNode` / `RenderNode` | Render node absztrakció |
| `OverlayLayer` / `OverlayRenderData` / `OverlayRenderPair` / `OverlayRenderItem` | Adat- és rétegmodellek |
| `OverlayDocumentHost` / `OverlayInstance` / `OverlayAnimationItem` | Host- és példánykezelés |

**Kritikus döntések (mérnöki, a fejlesztés során):**
1. **`ITransitionPlayer.Finished` interfészre emelése** — a `FigmaStateMachine` ne függjön konkrét playertől (a v0.3.7-ben F1-ként kivezettük; most jön vissza interface-szel)
2. **`TransitionItem.animationMode` bekötése** — a per-item Layout/Overlay mód tényleges használata (F22)
3. **Mikor él az Overlay pipeline?** — csak akkor, ha a profil/item Overlay módot kér; a Layout mód érintetlen marad (a regressziós bizonyíték)
4. **A StateMachine GoTo flow bővítése** — a Commit Overlay módban a rétegek összeolvasztását jelenti, nem teljes fa-cserét

**Első mérföldkő (MVP):** egyetlen valódi Overlay eset (pl. Dialog) végig — RenderPair, Binder, Layer, Player, Commit. A többi eset (Bottom Sheet, Popup, Dropdown, Context Menu, FAB Morph, Hero, Shared Element) ezután következik.
