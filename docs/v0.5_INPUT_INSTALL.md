# v0.5 — Input absztrakció (ADR-025): telepítés és teszt

> Az input-réteg interfésze: a runtime input-agnosztikus, a külső input
> (érintőfal, lidar) egyetlen interfészen csatlakozik.

---

## 1. Fájlok — mit másolj hova

| Fájl (workspace) | Cél (projekt) | Típus |
|---|---|---|
| `Assets/FigmaRuntime/Runtime/IFigmaFlowInput.cs` | `Runtime/` | **ÚJ** — az interfész |
| `Assets/FigmaRuntime/Runtime/FigmaFlowInputBase.cs` | `Runtime/` | **ÚJ** — a közös alap (deferred GoToState, cooldown, Activate) |
| `Assets/FigmaRuntime/Runtime/FigmaFlowPlaymaker.cs` | `Runtime/` | **CSERE** — a kattintás-észlelés az input pollozása (nem direkt ClickEvent) |

## 2. Mit ad ez most (a meglévő demókhoz)

- A `FigmaFlowInputBase` a közös mintát adja (a demók ebből származhatnak a jövőben — a viselkedésük változatlan)
- A PlayMaker mostantól **nem a ClickEvent-re figyel**, hanem az `IFigmaFlowInput.LastActivationTime`-ot pollozza — a kattintás és a külső input **egyformán** az idle-reset forrása
- A `Ping()` a külső inputnak (lidar/érintőfal) is jelez — a PlayMaker azonnal tudja

## 3. Elvárt viselkedés (változatlan a felhasználó számára!)

- A demók (Dialog/BottomSheet/Popup/Hero) **ugyanúgy működnek** (a deferred GoToState + cooldown a base-ben)
- A PlayMaker **ugyanúgy** reseteli az idle-t kattintásra
- **Új:** a külső input (a jövőben) az `IFigmaFlowInput`-on csatlakozik — a runtime-t nem kell módosítani

## 4. Teszt menet

1. Másold be a 3 fájlt → fordíts
2. **PlayMaker demó** (idle-return): kattints a UI-ra → az idle resetelődik (változatlan)
3. A demók (Dialog stb.) → változatlan
4. **Regresszió:** a teljes v0.5-ös stack (Preview/Sequence/Timeline, per-pair, rotation) → változatlan

## 5. Megjegyzések

- A demó input-kezelők (DialogDemoInput stb.) áttérése a `FigmaFlowInputBase`-re egy következő lépés — a minta már kész, az átállás nem változtat a viselkedésükön
- A jövőbeli lidar/érintőfal input: egy komponens, ami az `IFigmaFlowInput`-ot implementálja (pl. a lidar érintés-koordinátákat `GoToState`-re képezi, és `Activate()`-tal jelez)

## 6. Ha a kattintást nem érzékeli a PlayMaker (2026-08-02 hotfix)

**Ok:** a `FindInput()` `GetComponent<IFigmaFlowInput>()`-ot keres — ha a jeleneten NINCS ilyen komponens (a demó input-kezelők még a régi formában vannak), a pollozás sosem reseteli az idle-t → a kattintás nem "aktivál".

**Javítás (a friss `FigmaFlowPlaymaker.cs`):** a PlayMaker **közvetlen ClickEvent-fallbacket** kap — ha nincs `IFigmaFlowInput`, a saját UIDocument-jén figyeli a kattintást (`OnFallbackClick`). Így az idle-reset MINDKÉT esetben működik (a jövőbeli input-réteg az interfészen, a jelenlegi demók a fallbacken).

**A "csak 0→1 közt mozog" diagnózis:** a PlayMaker logikája a `states.Length`-t használja — a tünet oka a beállítás: (1) az `autoAdvanceSeconds` 0 (a diagnosztikai log jelzi), vagy (2) az `idleReturnSeconds` rövid → az idle mindig visszahúzza a 0-ra (az `idleReturnState = 0`), ezért csak a 0→1 indul el. **Beállítási tanács:** az `autoAdvanceSeconds`-t állítsd be (pl. 3s), az `idleReturnSeconds`-t HOSSZABBRA (pl. 60s), és ellenőrizd, hogy a `machine` mezőre a MEGFELELŐ gép van húzva (amelyiknek a `states` tömbjében a 3 állapot van).
