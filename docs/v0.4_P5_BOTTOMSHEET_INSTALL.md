## 2. Beállítás (új GameObject, pl. `BottomSheetDemo`)

1. `UIDocument` (Source Asset = NONE) + `FigmaDocumentHost` + `FigmaStateMachine` (states: [BottomSheet_Closed, BottomSheet_Open]) + `TransitionPlayer` + `OverlayRuntime` + `OverlayScene` + `OverlayTransitionPlayer` + `BottomSheetDemoInput` (machine → a StateMachine)
2. Profil: `animationMode = Overlay`
3. **TransitionAsset:** Motion Studio → Generate (előbb Play Mode-ban futtass egy átmenetet, hogy legyen Runtime Analysis) → az asset a StateMachine `transitionAsset` mezőjére
4. **A csúszó megjelenés beállítása:** az asset Inspectorában (Motion Studio) keresd meg a **`BottomSheetPanel`** itemet → állítsd az **Appear** mezőt **`SlideUp`**-ra (a `Backdrop` maradhat `Fade`)

## 3. Elvárt viselkedés

- **Megnyitás** (Megnyitás gomb): a `BottomSheetPanel` **alulról felcsúszik** (pozíció + fade-in), a Backdrop fade-in
- **Bezárás** (Bezárás gomb **vagy** kattintás a sötétítőre): a panel **lefelé csúszva eltűnik**, a Backdrop fade-out
- A panelen belüli kattintás (a gombon kívül) NEM zár (barrier)
- Nincs automatikus bezárás (a késleltetett GoToState + cooldown mintája a Dialog-ból)

## 4. Teszt menet

1. Play Mode → Megnyitás → a Console-ban: `[FigmaFlowDemo] OpenSheet -> GoToState(1)`, majd `Overlay prepared (N pairs)` → `Transition` → `Overlay commit completed.`
2. A panel a képernyő alján **látható marad** (a commit stabil)
3. Bezárás → lefelé csúszva eltűnik
4. **Regresszió:** a Dialog demo továbbra is fade-el (Fade mód — változatlan); a Shoes/Tabs Layout demók rendben

## 5. Hogyan működik (technikailag — ADR-015)

- A `TrackCandidate` jelöli a megjelenő/eltűnő elemeket (`IsAppear`/`IsDisappear`)
- A `Build` — ha az item `AppearMode.SlideUp` — a szintetikus oldalt az elem **saját magasságával lefelé tolja**, és `Position`-t ad a track-hez: megjelenés = alulról felcsúszás + fade-in, eltűnés = lefelé csúszás + fade-out
- A Motion Engine-hez NEM kell nyúlni (freeze tartva) — a meglévő `PositionTrack` + `OpacityTrack` végzi a munkát

## 6. Ha valami nem működik

- **A panel a képernyő tetejére csúszik / rossz irányba megy / nem csúszik csak fade** → **2026-08-02 hotfix #4:** a slide pozíciók az **élő elem geometriájából** számítódnak (`resolvedStyle`), a `FigmaStateMachine` **egy frame-et vár a `Prepare` után** (a UI Toolkit layout késleltetett — ez volt a `top=0 h=NaN` és a hibás capture-ből jövő `to.top=-176` oka). A capture csak fallback. **Három fájlt másolj be:** `Runtime/FigmaStateMachine.cs` + `Core/TransitionBuilder.cs` + `Experimental/Overlay/OverlayTransitionBuilder.cs` (az utóbbi a hívás miatt). A `[FigmaFlow] SlideUp appear: ... top=... h=...` lognak mostantól a **valódi** értékeket kell mutatnia (pl. `top=860 h=220` — a képernyő alja)
- **A panel rossz helyre csúszik (még a fix után is)** → **a StateCache ELÉRÜLT** — a slide az első dolog, ami a capture **pozíció-adatait** használja (a Fade csak az opacitást). Ha a cache egy korábbi UXML-verzióval készült, a `top` adat hibás → **exportáld újra a cache-t** (Play Mode → Motion Studio → Export State Cache → a StateMachine `stateCache` mezőjére)
- **A panel nem csúszik, csak fade-el** → a `BottomSheetPanel` item Appear mezője nem `SlideUp` (a Motion Studio-ban állítsd be), és a profil `animationMode`-ja Overlay
- **A per-item "Mode" (Layout/Overlay) mező a Motion Studio-ban:** jelenleg **tétlen** (F22 — a v0.4 per-item Overlay előkészülete). A pipeline-t a **profil** `animationMode`-ja vezérli. A demóhoz: **profil = Overlay**, az itemeknél a **Mode mindegy** (hagyhatod), az **Appear = SlideUp** a fontos
- **Semmi sem látszik** → a komponensek/sorrend ellenőrzése (lásd a P4 útmutatót); a Console logok (Overlay prepared / Transition / commit) alapján lépkedj

## 7. A "törölt asset + Next nem csinál semmit" magyarázata

**OK (2026-08-02, javítva):** a `FigmaStateMachine` eddig **blokkolta** a Next-et, ha a `transitionAsset` mező üres volt (védelmi guard). Ez munkafolyamat-holtpontot okozott: elemzés kell a Generate-hez, de asset kell az elemzéshez — tojás-csirke.

**A javítás (a `FigmaStateMachine.cs` új verziójában):** az üres asset **NEM blokkol** többé — a Next mindig lefuttatja az **elemzést** (a `CurrentAnalysis` feltöltődik), az átmenet pedig elemek nélkül, közvetlen commit-tal fut (figyelmeztető loggal). Ezzel a helyes munkafolyamat:

1. **Akár üres asset mezővel is:** Play Mode → Next → fut az elemzés (a panel közvetlenül, animáció nélkül vált — ez normális, még nincs asset)
2. **Motion Studio → Generate Transition Asset** → létrejön az asset az elemekkel (a `BottomSheetPanel` itemet itt állítsd **Appear = SlideUp**-ra)
3. **Az assetet a StateMachine `transitionAsset` mezőjére** húzni
4. **Újra Play Mode → Next** → most már az animáció is fut (a csúszással)

**Több demo egy jelenetben:** a `CurrentAnalysis` az **utolsó lefutott átmeneté** — a Generate azt használja. Ha a Dialog demo StateMachine-én nyomtál Next-et, az elemzés a Dialog elemeit adja. A megfelelő demo StateMachine-ének ContextMenu-jéből indíts (a GameObject neve alapján különböztesd meg), vagy ideiglenesen csak az egyik demo legyen aktív.
