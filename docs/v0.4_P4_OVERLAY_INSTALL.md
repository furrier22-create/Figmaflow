## 3. Teszt menet

1. **Play Mode indítás:** a logban `Overlay mód aktív (IOverlayDriver)` + `Overlay prepared (0 pairs)` (az első megjelenítésnél a pairs 0 — normális, mert nincs átmenet)
2. **Átmenet indítása** (Next / GoToState(1) / gomb):
   - `Overlay prepared (N pairs)` — N az animálható elemek száma
   - `[FigmaFlow] Transition` log — `Player: OverlayTransitionPlayer`
   - A dialog **megjelenik/animálódik** (opacity/position/size az asset beállításaitól függ)
3. **Vissza** (GoToState(0)): a dialog **eltűnik/animálódik vissza**
4. **Commit:** a logban `Overlay commit completed.` — a következő állapot stabil

## 5. Mi lett új a `FigmaStateMachine`-ben (ha kézzel illeszted)

1. `IOverlayDriver overlayDriver` mező + `useOverlay` + `overlayCommit` flag-ek
2. `Awake`: `GetComponent<IOverlayDriver>()`; ha `profile.animationMode == Overlay` és van driver → `SetPlayer(overlayDriver.Player)` + `useOverlay = true` (különben Layout)
3. `SetPlayer` helper (le-/feliratkozás a Finished-re) — a `SelectPlayer`/`SubscribePlayer`/`UnsubscribePlayer` kikerült
4. `ShowInitialState()`: Overlay módban `Prepare(states[0], states[0], null)` a scene-nel jelenít (nincs host.Load duplikáció); hiba esetén Layout fallback
5. `PlayTransition`: Overlay ág a driveren át (`Prepare → BuildTransition → Play`), `overlayCommit = true`; üres transition → közvetlen driver commit; prepare hiba → Layout fallback (`host.Load(current)`)
6. `OnTransitionFinished`: `overlayCommit` esetén `overlayDriver.Commit(...)`, különben `host.CommitState(...)`

## 6. Ismert határok / amire figyelj (a kutatási kód miatt)

- **Binder (2026-08-02 javítás):** az MVP-ben a binder **nem rejti el** a párokat — a trackek a Current elemeken animálnak, azokat látni kell. A hide/show az animációs reprezentáció (OverlayLayer) iterációhoz tartozik. Ha a régi `OverlayBinder.cs` van a projektben, az animáció láthatatlan (a commit végén csak "villan") — cseréld le!
- **UIDocument Source Asset = NONE** az overlay scene-eken — az `OverlayRuntime.Prepare` eltávolítja az idegen gyermekeket a host root-ból, de a tiszta beállítás a legjobb.
- A **target fa offscreen-re kerül** (`left/top: -100000`) a scene-ben — az animáció a capture adatokból (from/to ElementData) dolgozik; a **commit visszaállítja** a `left/top`-ot `Auto`-ra, így a látható állapot nem marad a képernyőn kívül (2026-08-02 fix)
- Ha a **párosítás hiányos** (`Missing pair` warning), a nevek nem egyeznek a két VTA-ban — a Figma exportban ellenőrizd
- Az **OverlayLayer** jelenleg üres marad (az animációs reprezentáció a következő iteráció — a trackek most a Current elemeken animálnak)
- A **dialog bezárásának input-kezelése** (kattintás a háttérre) még nincs implementálva — a teszthez a StateMachine gombjait használd (Next/GoTo0)
- **Awake sorrend:** az `OverlayRuntime` `Player`/`IsAvailable`/scene-init **lusta** (2026-08-02 javítás) — a `GetComponent` mindig működik, az Awake-ek sorrendje nem számít. A `FigmaDocumentHost` előbbisége a Script Execution Order-ben továbbra is ajánlott, de már nem kritikus.
- **Ha a `Transition` logban a `Player:` üres és NRE jön a PlayForward-nál** → a régi `OverlayRuntime.cs` van a projektben; a lusta inicializálásos verziót kell bemásolni (lásd §1)
- **Tesztelés:** két **jól elkülönülő** állapottal tesztelj (pl. dialog megjelenik/eltűnik) — ha a két állapot szinte azonos, az animáció alig észrevehető

## 6b. Dialog demo (P4-2) — a megjelenő/eltűnő elemek tesztje

> **⚠️ FONTOS:** a Dialog/BottomSheet/Popup demók **csak Overlay profillal** működnek
> helyesen. Ha a profil `animationMode = Layout`, a megjelenő elemek (panel, backdrop)
> **nem animálódnak és rossz helyen jelennek meg** (a Layout mód nem tudja a csak-célban
> létező elemeket kezelni — ADR-014). **Ellenőrizd: a profilban `Overlay` van-e.**

**A demó 3 fájlja:** `Samples/DialogDemo/DialogDemo_Closed.uxml` · `DialogDemo_Open.uxml` · `DialogDemoInput.cs`

**Mit mutat:**
- `DialogDemo_Closed`: címsor + "Megnyitás" gomb
- `DialogDemo_Open`: címsor + **Backdrop** (sötétítő) + **DialogPanel** (a "Bezárás" gombbal) — ezek a csak a célban létező elemek

**Beállítás (új GameObject, pl. `DialogDemo`):**
1. `UIDocument` (Source Asset = NONE) + `FigmaDocumentHost` + `FigmaStateMachine` (states: [Closed, Open]) + `TransitionPlayer` + `OverlayRuntime` + `OverlayScene` + `OverlayTransitionPlayer` + `DialogDemoInput` (machine → a StateMachine)
2. Profil: `animationMode = Overlay`
3. **TransitionAsset:** Motion Studio → Generate (Play Mode-ban futtass előbb egy átmenetet, hogy legyen Runtime Analysis) → az asset a StateMachine `transitionAsset` mezőjére

**Elvárt viselkedés:**
- **Megnyitás** (Megnyitás gomb): az OpenDialog gomb **fade-out**, a Backdrop + DialogPanel + Bezárás gomb **fade-in** (nem pattannak!)
- **Bezárás** (Bezárás gomb **vagy** kattintás a sötétítőre): a dialog elemek fade-out, az OpenDialog gomb fade-in
- A panelen belüli kattintás (a gombon kívül) NEM zár (barrier)

**Hogyan működik (technikailag):**
- A `TransitionBuilder.Analyze` mostantól a csak az egyik állapotban létező elemeknek is kandidátust ad (ADR-014): megjelenő = fade-in (szintetikus From, opacity 0), eltűnő = fade-out (szintetikus To, opacity 0)
- A Motion Engine-hez NEM kellett nyúlni (freeze tartva)
- A target konténer a valódi pozíción van (rejtve); a binder a megjelenő elemeket egyedileg láthatóvá teszi 0 opacitásról

**Regressziós figyelmeztetés (fontos!):** a Shoes/Tabs demókban mostantól az egyik állapotban hiányzó elemek **fade-elnek** — ez a kívánt Smart Animate viselkedés, de **újra kell tesztelni** a Layout demókat is!
